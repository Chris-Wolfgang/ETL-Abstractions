An extractor double that throws a transient fault on its first failFirstAttempts worker invocations and then succeeds, driven through a retry override of the Wolfgang.Etl.Abstractions 0.20 WrapWorkerExecution resilience seam. It both demonstrates how to build stream-level retry on a stage and serves as the reference component exercised by RetryContractTests (in Wolfgang.Etl.TestKit.Xunit).

Examples

// Fails twice, then succeeds on the third attempt (budget of 5):
var extractor = new RetryingExtractor<int>(Enumerable.Range(0, 10), failFirstAttempts: 2, maxAttempts: 5);
await foreach (var _ in extractor.ExtractAsync()) { }   // succeeds; extractor.AttemptCount == 3

Remarks

Each retry re-invokes the worker from the start (stream-level resilience, per the base contract). Because the transient fault is thrown at the start of the worker — before any item is yielded — a retried attempt never double-yields. After failFirstAttempts failures the worker yields every item; if the retry budget (maxAttempts) is exhausted first, the last fault propagates. AttemptCount records how many worker invocations occurred.

Retries the worker up to maxAttempts times: each attempt re-invokes workerFactory to produce a fresh stream, and a failed attempt is retried until the budget is exhausted, at which point the last fault propagates. Cancellation is never retried.
