Class ExtractorBase<TSource, TProgress>

Provides a basic implementation for data extractors that extract data of type TSource. Library authors can use this base class to create custom extractors by inheriting from it and implementing ExtractWorkerAsync and CreateProgressReport methods.

CurrentErrorItemCount

The number of items that raised an error and were discarded by the stage's error policy (OnItemError(ItemErrorContext) returned Skip) so far. This is distinct from CurrentSkippedItemCount, which counts items skipped intentionally (for example by SkipItemCount): a failed record is counted here, never silently dropped.

public int CurrentErrorItemCount { get; }

Property Value

int

CurrentItemCount

The current number of items extracted so far.

public int CurrentItemCount { get; }

Property Value

int

Remarks

It is the responsibility of the derived class to call IncrementCurrentItemCount() as each item is extracted. The base class has no way of knowing when an item has been processed.

This count is per run: it is reset to zero at the start of each run (when enumeration of an ExtractAsync result begins). Running the same instance more than once therefore reports the count for the current run, not a cumulative total across runs. Re-enumerating a single instance concurrently is not supported.

ErrorPolicy

Gets the policy invoked when an item fails to process. Return Skip to discard the item and continue, or Abort to re-throw and stop the run. Defaults to fail-fast: every failed item aborts the run until a policy is assigned. Ready-made policies are provided by Wolfgang.Etl.ErrorPolicies.ItemErrorPolicy. Assigned once, at construction (init-only), so the policy cannot change during a run.

MaximumItemCount

The maximum number of items to extract. Once the extractor has reached this limit, it should stop extracting and signal the end of the sequence.

public int MaximumItemCount { get; set; }

Property Value

int

Examples

var count = 0;
using (var reader = new StreamReader(filePath))
{
    while (!reader.EndOfStream)
    {
        yield return await reader.ReadLineAsync();
        count++;
        if (count >= MaximumItemCount)
        {
            Console.WriteLine("Maximum item count reached. Stopping extraction.");
            break; // Stop extracting if the maximum item count is reached
        }
    }
}

Remarks

This is useful for partially extracting data from a source, especially when the source is large or infinite or during development.

SkipItemCount

The number of items to skip before extracting. The extractor should skip the specified number of items before starting to yield results.

public int SkipItemCount { get; set; }

Property Value

int

Examples

using (var reader = new StreamReader(filePath))
{
    // Skip the specified number of items before starting to yield results

    var skipCount = 0;
    while (!reader.EndOfStream && skipCount < SkipItemCount)
    {
        await reader.ReadLineAsync();
        skipCount++;
    }

    // Now start yielding results

    var count = 0;
    while (!reader.EndOfStream)
    {
        yield return await reader.ReadLineAsync();
        count++;
    }
}

Remarks

This is useful for partially extracting data from a source during development, or to skip items that were already processed or are not relevant for the current extraction.

Exceptions

ArgumentOutOfRangeException

The specified value is less than 0.

WorkerResilience

Gets a resilience wrapper applied around the worker's execution — for example a retry / circuit-breaker / timeout strategy. The default is a no-op passthrough (the worker runs once), so behaviour is unchanged until a wrapper is assigned. Assign one — e.g. from a ready-made Wolfgang.Etl.* resilience package — to run the worker through a resilience pipeline without subclassing; the default WrapWorkerExecution(Func<CancellationToken, IAsyncEnumerable<TSource>>, CancellationToken) consults it. The wrapper receives a re-invocable worker factory (call it again to retry) and the run's CancellationToken, and returns the (possibly resilience-wrapped) item stream.

public Func<Func<CancellationToken, IAsyncEnumerable<TSource>>, CancellationToken, IAsyncEnumerable<TSource>> WorkerResilience { get; init; }

Property Value

Func<Func<CancellationToken, IAsyncEnumerable<TSource>>, CancellationToken, IAsyncEnumerable<TSource>>

Remarks

Assigned once, at construction (init-only); it cannot change during a run. This is stream-level resilience: the wrapper spans the whole worker, so a retry re-runs the entire extraction — per-item transient-fault retry belongs inside the worker. Overriding WrapWorkerExecution(Func<CancellationToken, IAsyncEnumerable<TSource>>, CancellationToken) is still available for stage-internal logic and takes precedence over this property unless the override calls base.

Exceptions

ArgumentNullException

The assigned value is null.

OnItemError(ItemErrorContext)

Decides what to do when an item fails to process. The base implementation delegates to ErrorPolicy (fail-fast by default). Override in a derived stage instead only when the decision needs stage-internal state; a worker does not call this directly.

protected virtual ItemErrorAction OnItemError(ItemErrorContext context)

Parameters

context ItemErrorContext

Describes the failed item — its ordinal, the exception, and optional raw content.

Returns

ItemErrorAction

Whether to skip the item or abort the run.

Remarks

A worker calls HandleItemError(ItemErrorContext), which invokes this method and performs the skip bookkeeping. The worker still owns the try/catch — a C# async iterator cannot resume after it throws — and calls HandleItemError(ItemErrorContext) from it. On a format that cannot genuinely resume after a bad record, Skip means "swallow the failure and stop at that point" rather than "skip and continue"; such a stage documents that on its own type.

WrapWorkerExecution(Func<CancellationToken, IAsyncEnumerable<TSource>>, CancellationToken)

A resilience seam wrapped around every invocation of ExtractWorkerAsync(CancellationToken). The default implementation simply invokes workerFactory once, so extraction behaves exactly as if the seam were absent. Override it to run the worker through a retry / resilience strategy (for example a Polly ResiliencePipeline): the strategy can invoke workerFactory more than once, each call producing a fresh stream, to retry a transient failure.

protected virtual IAsyncEnumerable<TSource> WrapWorkerExecution(Func<CancellationToken, IAsyncEnumerable<TSource>> workerFactory, CancellationToken token)

Parameters

workerFactory Func<CancellationToken, IAsyncEnumerable<TSource>>

A factory that produces a fresh worker stream for the supplied token. Re-invocable — call it again to retry.

token CancellationToken

A CancellationToken to observe, including during any retry delay.

Returns

IAsyncEnumerable<TSource>

The (possibly resilience-wrapped) stream of extracted items.

Remarks

This is stream-level resilience: a retry re-runs the whole worker from the start, so a failure part-way through re-yields items already seen. The per-run counters (CurrentItemCount, CurrentSkippedItemCount, CurrentErrorItemCount) are reset once at the start of the run, not on each retry, so they accumulate across attempts unless the override resets them. Any delay the override introduces must observe token. Kept dependency-free by design — a concrete Polly integration lives in a separate opt-in package rather than in this library.

Exceptions

ArgumentNullException

workerFactory is null.
