Examples

// In a dedicated net10.0 snapshot test project that references Verify.Xunit:
var loader = new SnapshotTestLoader<OrderRecord>(
    o => $"{o.Id}|{o.Customer}|{o.Total:0.00}");   // project + scrub as needed

await loader.LoadAsync(pipeline.ExtractAsync());

await Verify(loader.Snapshot);   // Verify owns the .verified.txt golden file + diff

Remarks

This loader is deliberately capture-only: it does no file I/O and takes no dependency on any snapshot framework, so referencing Wolfgang.Etl.TestKit never pulls one in. Run your pipeline into it, then pass Snapshot (or LoadedItems) to your own Verify(...) call in a dedicated snapshot test project — the fleet convention. The framework owns the golden .verified.txt file, the diff, and the approval workflow; this loader only produces the content to lock in.

Snapshot is one formatted line per item, joined by \n (a fixed line feed, not NewLine, so snapshots are stable across operating systems). Items are formatted with the delegate supplied to the constructor; the default is ToString(), which is diff-friendly for record types. Supply a custom formatter to project only the fields you care about and to scrub non-deterministic values (timestamps, GUIDs, auto-increment IDs) that would otherwise make the snapshot unstable.

Timing and progress are intentionally excluded from the snapshot — they are non-deterministic. Set SkipItemCount to skip the first N items and MaximumItemCount to cap how many are captured; each new LoadAsync call clears the buffer before it begins.
