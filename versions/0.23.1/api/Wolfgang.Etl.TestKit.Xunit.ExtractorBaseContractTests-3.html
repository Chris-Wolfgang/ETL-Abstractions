Examples

public class MyExtractorContractTests
    : ExtractorBaseContractTests<MyExtractor, MyRecord, MyProgress>
{
    protected override MyExtractor CreateSut(int itemCount) =>
        new MyExtractor("path/to/test-data.csv", itemCount);

    protected override IReadOnlyList<MyRecord> CreateExpectedItems() =>
        new List<MyRecord> { new("a"), new("b"), new("c"), new("d"), new("e") };
}

Remarks

Inherit from this class to get a comprehensive suite of contract tests covering all public behaviour defined by ExtractorBase<TSource, TProgress>:

  • All four ExtractAsync overloads yield the expected items.
  • Cancellation is honoured on all cancellable overloads.
  • CurrentItemCount is incremented as items are yielded.
  • ReportingInterval rejects values less than 1.
  • MaximumItemCount stops extraction at the specified limit.
  • MaximumItemCount rejects values less than 1.
  • SkipItemCount rejects values less than 0.
  • Progress callbacks fire at least once per extraction.
  • CreateProgressReport reflects CurrentItemCount.

You are responsible for implementing MaximumItemCount behaviour in your ExtractWorkerAsync override. The contract tests for MaximumItemCount will only pass if your extractor checks that property and stops yielding when the limit is reached.

Returns the expected items that the SUT should yield when created with CreateSut(int). Must return at least 5 items. The first itemCount items from this list are the expected output when CreateSut(itemCount) is called.

CreateSutOverSource(IEnumerable<TItem>)

Override to enable the "no over-read" tests for an extractor that reads from an injectable in-memory sequence. Return an extractor that draws its items from source, or null (the default) to skip those tests — appropriate for an extractor whose source is a connection or handle that cannot be a caller-supplied sequence.

Deprecated. The contract now drives progress timing via ManualProgressTimerCore and WithManualProgressTimer, which need no per-component timer plumbing — so overriding this is no longer required. Retained for source compatibility with existing overrides; remove your override (and the component's IProgressTimer-injection ctor) and it will be dropped in a future major version.

ExtractAsync_CurrentItemCount_tracks_each_yielded_item_Async()

Verifies that CurrentItemCount reflects the exact number of items yielded so far at every step of enumeration: it is 0 before the first item is pulled and equals k immediately after the k-th item is yielded.

[Fact]

Returns

Task

Remarks

This is a stronger guarantee than ExtractAsync_increments_CurrentItemCount_for_each_item_Async(), which only checks the final total. Enumerating one item at a time catches implementations that increment the counter at the wrong point relative to yield return (for example incrementing twice, or never updating the count until the sequence is fully drained).
