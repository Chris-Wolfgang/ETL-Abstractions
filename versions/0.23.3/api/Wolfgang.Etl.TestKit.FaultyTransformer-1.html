A pass-through transformer for testing error-handling paths. It returns each item unchanged like a normal transformer, but can be configured to inject deterministic faults — throwing at a given item, throwing after completion, or duplicating an item — so consumers can exercise mid-stream failure, finalization failure, and de-duplication logic without hand-rolling broken fakes.

Remarks

Faults are configured through the fluent ThrowAt(int, Exception), ThrowAfterCompletion(Exception), and DuplicateAt(int) methods, each of which returns the same instance so calls can be chained. Multiple faults stack on a single instance.

Fault indices are zero-based and refer to the position in the emitted (post-skip) sequence. A configured fault fires after IncrementCurrentItemCount() for that item, so a progress report reflects the item that caused the failure. When a ThrowAt(int, Exception) and a DuplicateAt(int) are configured for the same index, the throw takes precedence and the duplicate is not emitted. Calling ThrowAt(int, Exception) twice for the same index replaces the earlier exception (last-wins).

SkipErrors()

Configures the transformer to route every injected ThrowAt(int, Exception) fault through the base HandleItemError(ItemErrorContext) hook with a policy of Skip, so the failing item is discarded and counted as an error (CurrentErrorItemCount) rather than propagating. Use this to exercise a resumable stage's skip-and-continue path.

Remarks

Without an error policy an injected fault propagates (fail-fast), preserving the default behaviour. The failing item is not emitted, and its ItemErrorContext is recorded in CapturedErrors.

ThrowAt(int, Exception)

Configures the transformer to throw exception when it reaches the item at the specified zero-based index in the emitted sequence. The failing item is counted (its IncrementCurrentItemCount() runs) before the exception is thrown, so progress reflects the item that caused the failure, but the item itself is not emitted.
