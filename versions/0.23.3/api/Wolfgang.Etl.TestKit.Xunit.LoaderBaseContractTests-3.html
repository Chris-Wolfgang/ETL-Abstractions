Abstract base class providing xUnit contract tests for any type that inherits from LoaderBase<TDestination, TProgress>.

Examples

public class MyLoaderContractTests
    : LoaderBaseContractTests<MyLoader, MyRecord, MyProgress>
{
    protected override MyLoader CreateSut(int itemCount) =>
        new MyLoader(connectionString);

    protected override IReadOnlyList<MyRecord> CreateSourceItems() =>
        new List<MyRecord> { new("a"), new("b"), new("c"), new("d"), new("e") };
}

Remarks

Inherit from this class to get a comprehensive suite of contract tests covering all public behaviour defined by LoaderBase<TDestination, TProgress>:

  • All four LoadAsync overloads complete successfully.
  • Null guards on items and progress arguments.
  • Cancellation is honoured on all cancellable overloads.
  • CurrentItemCount is incremented as items are loaded.
  • ReportingInterval rejects values less than 1.
  • MaximumItemCount stops loading at the specified limit.
  • MaximumItemCount rejects values less than 1.
  • SkipItemCount skips the specified number of items.
  • SkipItemCount rejects values less than 0.
  • Progress callbacks fire when the timer fires.

You are responsible for implementing MaximumItemCount and SkipItemCount behaviour in your LoadWorkerAsync override.

CreateSourceItems()

Returns the source items used to feed the loader. Must return at least 5 items. The first itemCount items from this list are fed when CreateSut(itemCount) is called.

Creates the system under test configured to handle exactly itemCount items. The items fed to the loader must match the first itemCount items returned by CreateSourceItems().

CreateSutWithTimer(IProgressTimer)

Deprecated. The contract now drives progress timing via ManualProgressTimerCore and WithManualProgressTimer, which need no per-component timer plumbing — so overriding this is no longer required. Retained for source compatibility with existing overrides; remove your override (and the component's IProgressTimer-injection ctor) and it will be dropped in a future major version.

LoadAsync_stops_reading_source_at_MaximumItemCount_Async()

Verifies that the loader stops pulling items from its source once MaximumItemCount is reached, rather than draining the whole source and discarding the surplus. A loader that over-reads holds upstream resources (connections, cursors) far longer than necessary.

[Fact]
public Task LoadAsync_stops_reading_source_at_MaximumItemCount_Async()

Returns

Task

Remarks

The source is wrapped in a counter. Once the load completes with a limit of M, the wrapper must have observed at most M + 1 pulls — the +1 allows for the single read that discovers the limit has been reached.
