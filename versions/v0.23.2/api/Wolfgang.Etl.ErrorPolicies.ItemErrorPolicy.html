Ready-made policies for an ETL stage's error handling. Each is a
<xref href="System.Func%602" data-throw-if-not-resolved="false"></xref> from an <xref href="Wolfgang.Etl.Abstractions.ItemErrorContext" data-throw-if-not-resolved="false"></xref> to an
<xref href="Wolfgang.Etl.Abstractions.ItemErrorAction" data-throw-if-not-resolved="false"></xref>, so it can be assigned directly to a stage's <code>ErrorPolicy</code>
property (on <code>ExtractorBase</code> / <code>LoaderBase</code> / <code>TransformerBase</code>):

<example><pre><code class="lang-csharp">var deadLetters = new List<ItemErrorContext>();

var extractor = new SomeExtractor<Record>(source) { ErrorPolicy = ItemErrorPolicy.SkipDeadLetterAndLog(deadLetters, logger) };

The dead-letter overloads write to a caller-owned sink (a collection or a channel), so its size —
and therefore the memory a bad feed can consume — stays under the caller's control.

SkipAndDeadLetter(ICollection<ItemErrorContext>)

Records the failure in deadLetters (a "dead-letter" queue the caller owns), then discards the item and continues.

Func<ItemErrorContext, ItemErrorAction>

A policy that dead-letters and returns Skip.

Remarks

A single stage invokes this policy serially, so a plain List<T> is safe. If you share one collection across stages running concurrently, either supply a thread-safe collection or use the SkipAndDeadLetter(ChannelWriter<ItemErrorContext>) overload — the policy adds to the collection without locking.

Exceptions

ArgumentNullException

deadLetters is null.

SkipAndDeadLetter(ChannelWriter<ItemErrorContext>)

Writes the failure to deadLetters (a caller-owned channel) with TryWrite(T), then discards the item and continues. Because the hook is synchronous the non-blocking TryWrite is used, so a bounded channel that is full drops the failure — size the channel, or use BoundedChannelFullMode, accordingly.

SkipDeadLetterAndLog(ChannelWriter<ItemErrorContext>, ILogger)

Writes the failure to deadLetters with TryWrite(T) and logs it as a warning through logger, then discards the item and continues. See SkipAndDeadLetter(ChannelWriter<ItemErrorContext>) for the TryWrite caveat — but unlike that logger-less overload, when the write is dropped (a bounded channel that is full) this policy logs a distinct warning so the lost failure record is never silent.
