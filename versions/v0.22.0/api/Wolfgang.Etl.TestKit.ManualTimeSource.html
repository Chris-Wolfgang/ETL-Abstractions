A controllable time source for tests: time stands still until Advance(TimeSpan) is called, making a stage's Report timing metrics — Elapsed, ItemsPerSecond, PercentComplete, and EstimatedRemaining — deterministic rather than wall-clock-dependent.

Examples

var clock = new ManualTimeSource();
var extractor = new TestExtractor<int>(Enumerable.Range(0, 50).ToArray()).WithTimeSource(clock);
await foreach (var _ in extractor.ExtractAsync()) { }   // start timestamp captured from the frozen clock
clock.Advance(TimeSpan.FromSeconds(10));
// A report built now has Elapsed == 10s and ItemsPerSecond == 5.

Remarks

Attach it to an extractor / loader / transformer with WithTimeSource<TSource, TProgress>(ExtractorBase<TSource, TProgress>, ManualTimeSource) (and its loader / transformer overloads) before the run starts, then call Advance(TimeSpan) to move the clock forward by a known amount. The stage reads its start timestamp when the run begins, so a subsequent Advance(TimeSpan.FromSeconds(10)) makes Elapsed report exactly ten seconds.

This works because Wolfgang.Etl.TestKit is an internals-visible friend of Wolfgang.Etl.Abstractions, so it can supply the internal time-source seam the base classes read. The default epoch is a fixed constant so StartedAt is reproducible too.
